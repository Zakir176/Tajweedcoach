1. Introduction

1.1 Purpose
This document is the complete technical and functional specification for the Tajweed Recitation Coach — an AI-powered web application designed to help self-teaching Muslims improve their Quran recitation. It covers system requirements, architecture design, data models, API contracts, and the development roadmap.

1.2 Problem Statement
Millions of Muslims worldwide wish to recite the Quran correctly but lack access to qualified teachers, especially those in non-Arabic-speaking or diaspora communities. Current self-teaching methods such as YouTube videos and audio apps are entirely passive. They demonstrate what correct recitation sounds like but provide zero feedback on whether the learner is actually pronouncing correctly. There is no feedback loop for self-learners.

1.3 Proposed Solution
A voice-processing web application where users:
Select a Quranic verse they wish to practice
Record their recitation via browser microphone
Receive AI-generated feedback on accuracy and pronunciation errors
Hear reference audio of a qualified sheikh reciting the same verse

1.4 Scope
In Scope — MVP
  Verse selection by Surah and Ayah number
  In-browser audio recording via Web Audio API
  Arabic speech-to-text transcription using OpenAI Whisper
  Text comparison between transcription and correct Quranic text
  AI-generated human-readable feedback via LLM (Claude)
  Reference audio playback from EveryAyah.com per verse
  User progress tracking: verses practiced and accuracy over time
  Responsive PWA — works on desktop and mobile browsers

Out of Scope — MVP
  Real-time live feedback during recitation (post-MVP)
  Full tajweed rule engine: ghunna, idghaam, madd length detection (post-MVP)
  Offline mode
  Social or community features
  Multi-language UI: Arabic, Urdu (post-MVP)

5. System Architecture

5.1 Overview
The Tajweed Recitation Coach follows a three-tier client-server architecture with a dedicated AI processing pipeline. Each layer is independently deployable and scalable.

Architecture Layers
  Tier 1 — Presentation:   Vue 3 SPA / PWA (Vite build, Tailwind CSS)
  Tier 2 — Application:    Python FastAPI REST backend
  Tier 3 — Data:           PostgreSQL (relational) + Redis (cache and queue)
  AI Layer:                OpenAI Whisper (STT) + Claude API (feedback generation)
  External Services:       EveryAyah.com (audio CDN) and Quran.com API (verse text)

10. Development Roadmap

Phase 1 — Foundation (Weeks 1-2)
Sprint Goals
  Project scaffolding: Vue 3 + Vite frontend, FastAPI backend, Docker Compose setup
  PostgreSQL setup with Alembic migrations for all four tables
  Seed database with all 114 surahs and verse text from Quran.com API
  JWT authentication endpoints: register, login, refresh token
  Static verse display: Surah selector to Ayah selector to Arabic text renders on screen

Phase 2 — Core Loop (Weeks 3-4)
Sprint Goals
  AudioRecorder Vue component using Web Audio API
  FastAPI endpoint accepting audio file via multipart upload
  Whisper integration: transcribe uploaded Arabic audio with language=ar parameter
  Diff engine: compare transcription to expected verse text and compute accuracy score
  Return results to frontend and display basic word-level feedback to user

Phase 3 — Intelligence & Polish (Weeks 5-6)
Sprint Goals
  Claude API integration for human-readable error explanation in feedback
  EveryAyah reference audio player component with speed controls
  Word-level diff UI: green for correct, red for incorrect, gray for missing words
  Progress tracking: persist sessions to DB and render history view
  PWA manifest and service worker for mobile installability

Phase 4 — MVP Launch (Weeks 7-8)
Sprint Goals
  End-to-end testing of the full record, transcribe, feedback, and audio loop
  Performance optimization: caching and response time target under 8 seconds
  UI polish: loading states, error handling, full mobile responsiveness
  Deployment: backend on Railway or Render, frontend on Vercel
  Beta testing with 5 to 10 real users; collect and prioritize feedback
